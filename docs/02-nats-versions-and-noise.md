# 02 NATS 2.12 与 2.15：版本对比与测量噪声

## 结论

2.15.3 与 2.12.15 的性能没有差别，稳定性也一样。之前“2.15 吞吐只有 2.12 一半”的结论是测量误差，已经收回。

## 经过

用 `scripts/local/run-nats215.sh` 把整套对比在 2.15 上重跑了一遍（`results/local/07-nats-2.15-rerun.log`），64 个生产者同步发布只有 49.5k/s，排空 117k/s，大约是 2.12 那一次（90.8k/s、247k/s）的一半，服务端 CPU 也更低（约 65%，2.12 约 108%）。CPU 更低像是在等什么，于是排查：

1. **默认配置对比**：同样的容器限制下，`/varz`、`/jsz?config=true` 和 stream 配置没有实质差异（只多了几个默认关闭的 feature flag）；GOMAXPROCS 都是 2，都没有设置 GOMEMLIMIT。两个版本分别用 Go 1.25 和 Go 1.27 编译。
2. **不用容器**：把两个版本的二进制从镜像中取出，直接在宿主机上绑 2 个核运行：
   - 数据在 `/tmp`（tmpfs）时：2.12 121k/s，2.15 146k/s；
   - 数据在真实磁盘时：两个都是约 148k/s，CPU 消耗相同。
3. **容器限制逐项对比**（CPU 配额、内存限制分别打开）：两个版本互有高低，没有哪一项稳定地让 2.15 变慢，而且这一轮 2.15 在原始限制下反而更快（89.8k 对 78.3k）。
4. **交替多轮**（`scripts/local/ab-versions.sh`，`results/local/08-ab-2.12-vs-2.15.txt`）：

| 中位数（msg/s） | 16 个生产者同步 | 64 个生产者同步 | 异步写入 | 排空 |
|---|---|---|---|---|
| 2.12 | 57k | 73k | 223k | 169k |
| 2.15 | 60k | 73k | 227k | 218k |
| 范围（两个版本合计） | 44–67k | 48–94k | 182–369k | 166–254k |

同一个版本、同一个场景，单次结果可以相差近一倍。测试期间机器的 load average 在 6–8（6 核），桌面上的浏览器和 IDE 一直在抢 CPU；2.15 那一轮又正好和一次 Go 交叉编译重叠，落在最低端，2.12 那一轮落在高端。

## 教训

- 在有其他负载的机器上，**不要用单次结果比较版本**：交替运行多轮，报告中位数和范围。
- 测试期间不要在同一台机器上编译或做其他重活。
- 要绝对数值时用专用的机器（例如临时开一台云主机）。
- 涉及 fsync 的测试，数据目录不能放在 tmpfs 上（很多系统的 `/tmp` 是 tmpfs）。
- CPU 更低、吞吐更低时，先排除“被别的进程抢走了 CPU”，再去找锁和 IO。

## 2.15 的稳定性（与 2.12 相同）

| 场景 | 2.15 |
|---|---|
| broker kill -9 或重启 | 不丢 |
| broker 和 worker 同时 kill -9 | 不丢 |
| 20 万条延迟 NAK 后 kill -9 | 全部恢复 |
| 60 万条延迟 NAK 的内存 | 约 195MB |
| 延迟 NAK 占满 MaxAckPending 后卡住 | 仍然存在（5000 条只延迟了 1000 条） |
| 10k/s 持续 10 分钟 | 不丢不重，每 10 秒窗口 p99 1.7–9.6ms（上限偏高，很可能也是同样的干扰） |
| 积压 300 万条再排空 | 正常，没有 OOM |
